- The server half is reproduced. One file has a `schema` error. A `codeAction` with no
  diagnostics, at 130 positions of that file and at 130 positions of another file, is answered
  `-32803` every time, naming `b.ddd.json`.
- The toast half is the client's. In the library, the code action request fails through
  `handleFailedRequest(type, token, error, null)`, whose `showNotification` defaults to true.
  `error()` then calls `showErrorMessage("Request textDocument/codeAction failed.", "Go to
  output")`, because `revealOutputChannelOn` defaults to `Error` and `extension.ts:48-55` does not
  change it.
- So a toast naming no file at each request is what the code reads, but nobody saw it in an
  editor. One session that puts the caret in a project with a broken file would settle it.
- If the toast is real the grade is Important. If it is not, the error answer still hides every
  fix and says why only in the output channel.

  preview first", and the module docstring at `src/ddd/lsp/edits.py:8-10` rests on the same claim.
