# Plotting an object's values — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Under every values grid, draw the numbers it holds — a polyline per row, over the axis they are laid against — so that a reader sees the shape instead of imagining it.

**Architecture:** One pure module turns a `ValuesReply` into geometry in a fixed `viewBox`; one component draws that geometry as SVG and holds no state; `ValuesGridView` renders it between the table and the offer. **No screen change and no server change** — the reply already carries every number the picture needs.

**Tech Stack:** React 19, React Aria, Vitest, Playwright, Ladle. Hand-rolled SVG: the page has no charting dependency and gains none.

**Spec:** [`docs/superpowers/specs/2026-09-25-gui-plots-design.md`](../specs/2026-09-25-gui-plots-design.md)

- Axes: `CurveA` and `CurveB` carry `axis → AxisA`; `MapA` carries `x_axis → AxisA` and `y_axis → AxisB` (`%`, ×0.5, raw `[0, 60, 140, 200]`, reading `0, 30, 70, 100`); **`BlockA` and `AxisA` carry none**.
- **`AxisA`'s breakpoints are unevenly spaced**: raw `0, 3200, 6400, 12800, 19200, 32000`, reading `0, 800, 1600, 3200, 4800, 8000`, so the gaps are 800, 800, 1600, 1600 and 3200.
- **`BlockA` and `AxisA` are the only two objects whose limits fall inside their own values** — both span exactly their limits, so both limit lines land on the extremes. This is why the range is padded.
- `ValuesReply.minimum` and `.maximum` are the **physical** limits. In raw counts they must be converted back with `rawOf`, or the lines are drawn in the wrong units.

```ts
/** The drawn box, in the `viewBox`'s own units. The plot area is what is left inside the
 * margins: the left one holds the y readings, the bottom one the x readings. */
export const BOX: { width: 640; height: 200; left: 56; right: 16; top: 8; bottom: 28 };

export interface PlotPoint { x: number; y: number }

export interface PlotLine {
  /** What this row is called - a map's own `AxisB` reading - and `""` for a single row,
   * whose name is the y label instead. */
  label: string;
  points: PlotPoint[];
}

export interface PlotRule {
  /** The reading the line marks, as the y label's unit measures it. */
  value: number;
  y: number;
}

export interface Plot {
  lines: PlotLine[];
  /** One per breakpoint or index, with the text the grid's own column header uses. */
  ticks: { x: number; label: string }[];
  /** The declared limits that fall inside the drawn range - neither, one or both. */
  rules: PlotRule[];
  /** `AxisA (Hz)` under the plot, `""` where the values are laid against indices. */
  xLabel: string;
  /** `CurveA (ms)` - the object's own name, reaching only the picture's accessible name and its
   * tooltip; the side itself draws `low` and `high`, not this. */
  yLabel: string;
  /** The drawn range, for the two y readings. */
  low: number;
  high: number;
}

/** Everything the picture needs, from the reply the grid is already showing. */
export function plotted(reply: ValuesReply, physical: boolean): Plot;
```

```ts
import type { ValuesReply } from "../api/types";
import { columnHeader, labelled, physicalOf, rawOf, rowHeader } from "./objectValues";

/** The drawn box, in the `viewBox`'s own units - one fixed frame scaled to whatever width the
 * component is given, so the drawing is resolution-free and its screenshot is stable. The left
 * margin holds the two y readings, the bottom one the x readings. */
export const BOX = { width: 640, height: 200, left: 56, right: 16, top: 8, bottom: 28 } as const;

export interface PlotPoint {
  x: number;
  y: number;
}

export interface PlotLine {
  label: string;
  points: PlotPoint[];
}

export interface PlotRule {
  value: number;
  y: number;
}

export interface Plot {
  lines: PlotLine[];
  ticks: { x: number; label: string }[];
  rules: PlotRule[];
  xLabel: string;
  yLabel: string;
  low: number;
  high: number;
}

const PAD = 20;

/** The axis the columns are laid against, which a map states as `x_axis` and a curve as `axis`. */
function columnAxis(reply: ValuesReply) {
  return reply.axes.find((axis) => axis.position === "x_axis") ??
    reply.axes.find((axis) => axis.position === "axis");
}

/** Where the values sit along the bottom: the axis's own readings where there is one, and the
 * indices otherwise - which are evenly spaced because they are, while breakpoints are not. */
function alongTheBottom(reply: ValuesReply, physical: boolean): number[] {
  const axis = columnAxis(reply);
  if (axis === undefined || axis.breakpoints.length === 0) {
    return reply.rows.flatMap((row) => row.map((_, index) => index)).slice(0, widthOf(reply));
  }
  return axis.breakpoints.map((raw) => (physical ? physicalOf(raw, axis.conversion) : raw));
}

/** How many values a row holds - the shape's last dimension, and 0 for a shape of none. */
function widthOf(reply: ValuesReply): number {
  const [first = 0, second] = reply.shape;
  return second === undefined ? first : second;
}

/** The range the values are drawn in: their own span with a twentieth of it to spare above and
 * below, so a limit that falls on an extreme - which is where both of `BlockA`'s fall - is drawn
 * inside the frame rather than clipped to its edge.
 *
 * A span of zero has no twentieth worth taking, and a scale built on it divides by zero: an
 * object stating one value for every element is real (`CurveB`) and so is one stating none at
 * all. Such a range is the value with a twentieth of *itself* either side, or one either side
 * where the value is zero and there is no proportion to take. */
function rangeOf(values: number[]): [number, number] {
  const low = Math.min(...values);
  const high = Math.max(...values);
  if (low !== high) {
    const pad = (high - low) / PAD;
    return [low - pad, high + pad];
  }
  const span = low === 0 ? 1 : Math.abs(low) / PAD;
  return [low - span, low + span];
}

/** A reading's place in the box, from a range to a side of it. */
function placed(value: number, from: number, to: number, start: number, length: number): number {
  return from === to ? start + length / 2 : start + ((value - from) / (to - from)) * length;
}

export function plotted(reply: ValuesReply, physical: boolean): Plot {
  const xs = alongTheBottom(reply, physical);
  const values = reply.rows.flatMap((row) =>
    row.map((raw) => (physical ? physicalOf(raw, reply.conversion) : raw)),
  );
  const [low, high] = rangeOf(values);
  const across = BOX.width - BOX.left - BOX.right;
  const down = BOX.height - BOX.top - BOX.bottom;
  const xAt = (index: number) =>
    placed(xs[index] ?? 0, Math.min(...xs), Math.max(...xs), BOX.left, across);
  const yAt = (value: number) => BOX.top + down - (placed(value, low, high, 0, down) - 0);
  const labels = reply.shape.length === 1 ? reply.rows.map(() => "") : rowHeader(reply, physical);
  const axis = columnAxis(reply);
  return {
    lines: reply.rows.map((row, index) => ({
      label: labels[index] ?? "",
      points: row.map((raw, at) => ({
        x: xAt(at),
        y: yAt(physical ? physicalOf(raw, reply.conversion) : raw),
      })),
    })),
    ticks: columnHeader(reply, physical).map((label, index) => ({ x: xAt(index), label })),
    rules: [reply.minimum, reply.maximum]
      .map((limit) => (physical ? limit : rawOf(limit, reply.conversion, reply.datatype)))
      .filter((value) => value >= low && value <= high)
      .map((value) => ({ value, y: yAt(value) })),
    xLabel: axis === undefined ? "" : labelled(axis.name, axis.unit, physical),
    yLabel: labelled(reply.name, reply.unit, physical),
    low,
    high,
  };
}
```

**Two notes for the implementer.** `alongTheBottom`'s index branch is clumsy as written above —
what it must answer is `[0, 1, … width - 1]`, and any spelling that does so without an unreachable
fallback is better; say in your report which you used. And `yAt` inverts the y direction because
SVG counts downwards while a plot counts upwards: a value at `high` sits at `BOX.top`.

```tsx
import type { ValuesReply } from "../api/types";
import { BOX, plotted } from "../lib/valuePlot";

export interface ValuesPlotViewProps {
  reply: ValuesReply;
  physical: boolean;
}

/** The numbers above, as a picture. One polyline per row with a marker at each point, the axis
 * named below and the object beside, and the declared limits ruled across where they fall inside
 * the drawn range - which is the one thing the table deliberately does not show (spec 4).
 *
 * `role="img"` with a name of its own: every number in here is in the table above, so a reader
 * who cannot see the drawing loses nothing by being told what it is rather than what it holds. */
export function ValuesPlotView({ reply, physical }: ValuesPlotViewProps) {
  const plot = plotted(reply, physical);
  const inside = BOX.height - BOX.top - BOX.bottom;
  return (
    <svg
      className="values-plot"
      viewBox={`0 0 ${BOX.width} ${BOX.height}`}
      role="img"
      aria-label={`${plot.yLabel} plotted against ${plot.xLabel === "" ? "its indices" : plot.xLabel}`}
    >
      <title>{`${reply.name}, drawn`}</title>
      {plot.rules.map((rule) => (
        <line
          key={rule.value}
          className="values-plot-rule"
          x1={BOX.left}
          x2={BOX.width - BOX.right}
          y1={rule.y}
          y2={rule.y}
        />
      ))}
      <line
        className="values-plot-axis"
        x1={BOX.left}
        x2={BOX.width - BOX.right}
        y1={BOX.top + inside}
        y2={BOX.top + inside}
      />
      {plot.ticks.map((tick) => (
        <text key={tick.label} className="values-plot-tick" x={tick.x} y={BOX.height - 8}>
          {tick.label}
        </text>
      ))}
      <text className="values-plot-side" x={4} y={BOX.top + 8}>
        {String(plot.high)}
      </text>
      <text className="values-plot-side" x={4} y={BOX.top + inside}>
        {String(plot.low)}
      </text>
      {plot.lines.map((line) => (
        <g key={line.label || reply.name} className="values-plot-line">
          {line.points.length > 1 && (
            <polyline points={line.points.map((p) => `${p.x},${p.y}`).join(" ")} />
          )}
          {line.points.map((point) => (
            <circle key={`${point.x},${point.y}`} cx={point.x} cy={point.y} r={2.5} />
          ))}
          {line.label !== "" && line.points.length > 0 && (
            <text
              className="values-plot-row"
              x={BOX.width - BOX.right}
              y={line.points[line.points.length - 1]?.y ?? 0}
            >
              {line.label}
            </text>
          )}
        </g>
      ))}
      <text className="values-plot-name" x={BOX.left} y={BOX.height - 8}>
        {plot.xLabel}
      </text>
    </svg>
  );
}
```

**Two things to settle while writing it.** A `key` built from a label is only unique while the
labels are — a map whose y axis repeats a reading would collide, and so would two points at the
same place; prefer the index where that is a risk and say what you chose. And the `?? 0` above is
the kind of unreachable fallback part 9 had to delete from this very area: if the gate or your own
reading says nothing can reach it, write it so that nothing needs to.
