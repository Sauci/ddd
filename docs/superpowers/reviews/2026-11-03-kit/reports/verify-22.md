**M6 (confirmed, raised to Important).** I re-applied the four mutants together in a fresh copy (d22). The whole suite, `test_cmake` and `test_transcripts` included, ends with the baseline's three environmental failures. Each effect reproduced, every command in a process of its own (`eff/cli-effects.txt`). `ddd id a.ddd.json` without `--assign` exits 0 and writes an id, where the tree exits 2 and leaves the file untouched. `check --format xml` exits 1 with the text report, where the tree exits 2. `generate a2l` of the demo, with neither `--byte-order` nor `--image`, writes `BYTE_ORDER MSB_FIRST`, where the tree writes `MSB_LAST`. And `_port('65535')` is refused. I raise the grade for the byte order. That default is what every CMake build reaches when it states no `BYTE_ORDER` and takes no addresses from the image, because `cmake/Ddd.cmake:578-579` passes `--byte-order` only when one is given. `tests/test_cli.py:3772-3773` pins the constant the help names, not the default the generate path applies. So a one-token regression would give every such project an a2l with the wrong byte order, and the whole suite would stay green. That is a gap in front of wrong output an integrator would ship, which is Important.
