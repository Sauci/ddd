**I1, confirmed, Important kept** (`p18_i1.txt`, `p18_i1.py`).
- My projects: one types file of structures with ten `uint8` members each, one constants file of
  `K0..Kn`, one component with one local variable carrying an id. Every run is clean: exit 0, no
  finding.
- Through `ddd check --format json`: with 40,000 members, 1.4 s without constants, then 5.7, 10.7,
  20.3 and 41.2 s for 500, 1,000, 2,000 and 4,000 constants. With 1,000 constants, 2.1, 5.8 and
  10.7 s for 10,000, 20,000 and 40,000 members. The cost is linear in each factor, about 0.24 µs
  per constant and member, so it grows with the square when a project grows in both.
- In process at 2,000 constants and 40,000 members, `analyze` takes 18.6 s. Timed, 20.1 s of a
  20.7 s run are spent inside the 2,000 calls of `_members_named`. The same method answered from
  an index built once brings `analyze` to 0.54 s.
- Size: the cost depends on constants and members, not on declarations, so the large-projects
  spec's 35,000 to 100,000 declarations bound it in neither direction. A second of extra analysis
  needs constants times members near 4 million: 1,000 constants and 4,000 members, or 400 and
  10,000. That is a modest constants file next to a few hundred structures, which a project at
  that scale plausibly has, and it is paid with no finding, on every analysis, by the build, each
  save in the language server and each revision of `ddd gui`. `tools/generate_project.py` has no
  option for types or constants, so the benchmark cannot see it. Important stays, on that
  plausibility; with a few hundred constants and members it is a fraction of a second.

**M2, confirmed with a correction of who meets it** (`p18_m2_types.txt`,
`p18_m2_units.txt`, `p18_m2_cycle.txt`).
- The cost is per finding times the vocabulary. Every declaration naming `Gone_t` costs 2.7 ms a
  finding among 1,500 types and 5.6 ms among 3,000, at 3,500 and at 7,000 declarations alike.
  A unit outside the file costs 2.1 ms a finding among 150 units and 4.2 to 4.5 ms among 300.
  One cycle of 1,000, 2,000 and 4,000 structures takes 1.2, 4.3 and 17.1 s.
- The correction: the pass's first example, "a types file lost in a merge", leaves no type to
  sweep. With the types file dropped, 6,990 `unknown-type` findings take 2.7 s, against 1.9 s
  clean. What pays is a large vocabulary that is still present while many uses fall outside
  it: a removed or renamed type among thousands, or a units file adopted with part of the
  units.
- Minor stays: the state lasts until the mistake is fixed, and the answer is right.
