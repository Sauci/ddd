No candidate of pass 6 is refuted or left plausible, and no grade changes. Three confirmations
carry corrections, and one confirmation rests on the standard's letter.

Every run was mine, on throwaway files under `verify-5-6/p6/`, with the review tree's `ddd.exe`
0.11.0. The published schemas were checked with the venv's `jsonschema` 4.26 (run with `-I`).
gcc was MinGW gcc 15.2 under the CI flag set of `docker/compile.sh`. M12 ran in Windows
PowerShell 5.1 with `-NoProfile`. The pass's probes served only to tell me what to try; for M5(c)
I read its `e14_small.py` to find the trigger it used.

**I2, confirmed; the grade rests on the standard's letter.**
- What I saw: `generate a2l --strict` exits 0 with no finding (`p6/i2.txt`). The A2L carries
  strings of 300 and 316 characters, a 296-character `SYMBOL_LINK` for eight levels of
  32-character members, and a 2144-character record name for 64 levels.
- ASAP2 1.6.1 sets the limits: a `string` is at most `MAX_STRING` 255 and an `ident` at most
  `MAX_IDENT` 1024. `SYMBOL_LINK`'s `SymbolName` and `LongIdentifier` are strings.
- What I could not test: whether CANape, INCA or a delivery checker refuses, cuts or reads the
  excess.
- Why it stays Important: the file breaks the standard on an ordinary project, with a clean exit
  under `--strict`. If the target tools read long strings anyway, Minor would be the right grade.

**M4, confirmed with a correction** (`p6/m4.txt`).
- What holds: a duplicate key, `NaN` or `Infinity` gets a finding at the file alone, with no line
  and no pointer.
- The correction: the docstring the pass cites (`loading.py:1260-1264`, "a located finding")
  belongs to `_read_text`. That function is about reading the file, and the parse happens in
  `parse_json_text`.
- So the promise this breaks is the spec's own reason for refusing the key: "costly to locate"
  (`SPEC.md:206-209`).

**M5, confirmed with corrections** (`p6/m5.txt`).
- (a) A lone surrogate in a description passes `check` and stops `dump`, `dump -o`, `generate c`
  and `generate a2l`. `ddd list` fails only when the surrogate is in a unit, the field it prints.
- (b) An infinity in a plugin's block checks clean and dumps as `null`.
- (c) A block nested 100 levels needs `unknown-extension` relaxed, which is an error by default.
  With a plugin whose model takes the block, `check` itself exits 2 in the plugin's words. Only
  with the check relaxed do I get the pass's "`check` clean, `dump` exit 2".
- (d) The 64-bit offset is as the pass says.

**M8, confirmed with a correction** (`p6/m8.txt`, `src/ddd/lsp/hover.py:162-181`).
- What holds: a scalar or external type's description reaches no file that
  `generate all --dictionary` writes, C, A2L or dictionary. The C model hands no such type to the
  templates, so the published "offered to the c templates" is false.
- The correction: the editor's hover does show both descriptions. "Reaches nothing" is true of
  the outputs only.
